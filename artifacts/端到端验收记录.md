### 复核（engine2）与降级

* 设计：复核引擎**仅在主引擎结果低置信时**才被调用。

* 因此**降级路径（复核超时/504 → `engine2_failed`）本次未在真实链路上触发**，它由自动化测试覆盖

## 5. 联调中发现并修复的问题

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 单端口部署下访问 `/present/1`、`/essays/1/proofread` 等深层路由 **404 白屏** | `StaticFiles(html=True)` 只为目录请求回退 `index.html`，不做 SPA 深层路由回退 | `backend/app/main.py` 新增 `_SpaStaticFiles`：非 `api/` 前缀的 404 回退到 SPA 入口（生产环境老师收藏/刷新深层链接必需） |
| 2 | 页面渲染出 T01 期骨架文案「交互将在后续任务（T03/T04）中实现」 | `frontend/dist` 是 **T01 期陈旧构建**，不含 T03/T04 页面 | 重新 `npm run build` 产出当前 dist；并再次校验截图 |
| 3 | 校对页无 diff 时文案「复核引擎可能已降级」误导 | 高置信稿件本就**不调用**复核引擎，并非降级 | `frontend/src/components/DiffText.tsx` 文案改为中性准确表述 |
| 4 | `vite build` 清空 `dist` 被沙箱 safe-delete shim 拦截（`count>50`） | 受控环境的批量删除保护（**环境问题，非代码缺陷**） | 构建前先删 `dist` 再 `vite build`；普通 CI/服务器无此问题（已记入 README 常见问题） |

## 6. 结论

* **一期核心链路在真实引擎下端到端跑通**：名单导入 → 建期 → 拍照上传 → 真实 OCR → 置信度判定 →
  校对定稿 → 三套模板成册 PDF → 投屏/校对页渲染，全部成功，无人工干预。
* 性能符合预期：单篇主引擎识别 **8–14s**（快通道），三套 PDF 导出 ~28s。
* 置信度路径：本次全部高置信，复核引擎未介入；降级路径由自动化测试覆盖。
* 遗留的**视觉观感**与**真机项**见下节。

### 真机待确认（只能由老板/老师在真实设备与网络确认）

   若触发低置信，观察复核引擎（`qwen3.7-flash`）是否返回、是否发生 504 降级（`task.error` 可见）。
2. **课堂投屏**：投影/大屏分辨率与字号观感（当前为 1920×1080 定稿）。
3. **打印张贴**：单篇版式 PDF 的实际纸张边距与装订效果。
4. **生产网络**：域名 / HTTPS / nginx 反代在生产网络的连通性与证书。
5. **口令安全**：上线前将默认口令 `admin123` 改为教师自设口令（见 README「口令」节）。
6. **数据落盘**：`EWB_DATA_DIR` 的生产路径与磁盘/备份策略。
