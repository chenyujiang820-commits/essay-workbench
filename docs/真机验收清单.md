## 2. 识别质量（本期唯一真实校准机会）

> v1.1 的实测用的是网络样本（Q6 已决定取消班级复测）。**本节就是班级复测**，用真实字迹补齐。

统计方式：随机抽 **20 篇**，每篇数「黄标存疑处」和「需要老师动手改的字数」。

| 指标 | 记录 | 达标线 |
|---|---|---|
| 整篇零改动即可用的篇数 | ＿＿ / 20 | — |
| 校对耗时中位数（分钟/篇） | ＿＿ | **≤ 3** |
| 校对耗时最长的一篇 | ＿＿ | — |
| 出现「编字」（识别出一个看起来通顺但原稿没有的词）的篇数 | ＿＿ / 20 | 记录，不卡验收 |
| 低置信横幅触发的篇数 | ＿＿ / 20 | 应与潦草程度大致相符 |
| 全部 45 篇跑完的总时长（分钟） | ＿＿ | **≤ 5**（v1.2 并发后目标） |
| 同一批的并发对比（可选，各跑一次） | 串行 ＿＿ 分钟 / 并发4 ＿＿ 分钟 | 并发4 达到串行的 **≤40%** 即可；
  PRD 原文的 ≤25% 是 4 消费者的理论下限，mock 实测只能到 **32.3%**（每篇一个独立 DB session 的
  固定开销 ≈122 ms/篇 占比过大），照字面判会把正确实现判成失败 |

补记：哪一类字迹最容易错（连笔 / 涂改多 / 格子纸 / 光线暗）＿＿＿＿＿＿＿＿＿＿
是否出现复核引擎失败（看板里该篇任务详情有 `engine2_failed`）：☐ 否 ☐ 是（约 ＿＿ 篇）

- [x] **归档权限落盘为 0600**：rev.3 已在 Linux（WSL2，`/tmp` 为 tmpfs）实测通过 —— 归档 `mode=600`、
      进程 umask `0o22`（说明是显式 chmod 生效而非继承）、同目录另建 0644 文件作负对照、
      `--verify` 通过、tar 成员均为相对路径。生产机上线时仍按 `ls -l /var/backups/essay-workbench/`
      再确认一次（文件系统与 umask 可能不同），并确认归档不在数据目录内。
- [ ] 登录限速实测：同一来源连错 5 次后第 6 次返回 429，等约 1 秒后可用正确口令登录
